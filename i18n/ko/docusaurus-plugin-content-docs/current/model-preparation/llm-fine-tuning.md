# LLM 미세조정(fine-tuning)

미세조정(fine-tuning)은 LLM을 특정 사용 사례에 맞게 조정하는 가장 효과적인 방법
중 하나입니다. 사전학습된 모델에 작업별 새 데이터를 사용해 학습 과정을 이어
갑니다. 이때 모델 전체를 업데이트할 수도 있고, 특정 레이어만 업데이트할 수도
있습니다.

미세조정을 하는 핵심 이유는 효율성입니다. 모델을 처음부터 학습시키는 일은 자원이
매우 많이 듭니다. 대규모 데이터셋에서 일반적인 언어 패턴을 이미 학습한 베이스
모델(base model)을 바탕으로 삼는 편이 훨씬 쉽고 비용 효율적입니다. 미세조정은
이런 폭넓은 능력을 특정 작업에 맞게 다듬어 줍니다.

예를 들어 미세조정을 하면 모델의 다음 측면을 크게 개선할 수 있습니다:

- **도메인 전문성**: 법률, 의료, 프로그래밍 관련 작업에 맞게 모델을 조정합니다.
- **지시 따르기**: 모델이 응답에서 특정 형식, 어조, 문체를 지키도록 합니다.
- **안전성과 정렬(alignment)**: 민감하거나 위험도가 높은
  [프롬프트](/model-interaction/prompt-engineering/)를 모델이 다루는 방식을
  강화합니다.

## 커스터마이징 스택에서 미세조정의 위치 {#where-fine-tuning-fits-in-the-customization-stack}

미세조정은 커스터마이징 방법 중 하나일 뿐입니다. 미세조정은 모델 가중치를
바꿉니다. 이 점에서
[프롬프트 엔지니어링](/model-interaction/prompt-engineering/),
[함수 호출](/model-interaction/function-calling/),
[구조화된 출력](/model-interaction/structured-outputs/) 같은 다른 기법과
다릅니다.

이 차이는 프로덕션에서 중요합니다. 런타임 기법은 대개 테스트가 더 빠르고,
되돌리기 쉬우며, 여러 모델 공급자 사이에서 이식성이 더 높습니다. 미세조정은
원하는 동작이 안정적이고, 많은 요청에 걸쳐 나타나며, 프롬프트나 검색한
컨텍스트만으로는 깔끔하게 처리할 수 없을 때 더 적합합니다.

실제 개선 루프는 보통 다음과 같습니다:

1. 실제 입력이나 대표적인 입력으로 평가 세트를 만듭니다.
2. 프롬프트, 예시, 검색, 도구, 출력 검증을 개선합니다.
3. 같은 평가 세트로 결과를 측정합니다.
4. 남은 실패가 일정한 패턴을 띠고 모델 안으로 옮길 가치가 있을 때만
   미세조정합니다.

## 흔히 쓰는 미세조정 프레임워크 {#common-fine-tuning-frameworks}

LLM을 미세조정한다고 해서 모든 것을 처음부터 만들어야 하는 것은 아닙니다. 이
과정을 간소화하도록 설계된 오픈소스 프레임워크가 여럿 있습니다.

이런 도구는 사용자 정의 데이터셋으로 오픈 웨이트 모델을 학습시키는 기능을 바로
쓸 수 있는 형태로 제공합니다. 복잡한 학습 코드를 직접 작성하지 않고도 최신
최적화 기법을 쉽게 적용할 수 있습니다.

이 프레임워크 중 다수는 효율성도 염두에 두고 만들어졌습니다. 제한된
하드웨어에서도 메모리 사용량을 줄이고 학습 속도를 높이도록 돕습니다.

### Axolotl {#axolotl}

[Axolotl](https://axolotl.ai/)은 LLM의 사후 학습을 단순하게 만들어 주는 사용하기
쉬운 미세조정 프레임워크입니다. 전체 미세조정, 지시 미세조정, LoRA/QLoRA, 정렬
작업 중 무엇을 하든 학습 내부 구조를 깊이 파고들지 않고 쉽게 시작할 수 있습니다.

Axolotl은 Hugging Face의 Transformers 라이브러리를 기반으로 만들어졌지만, 복잡한
부분의 상당수를 깔끔한 YAML 기반 설정 시스템으로 감쌉니다. 데이터셋, 모델, 학습
전략 같은 학습 설정을 설정 파일 하나에 정의하면 나머지는 Axolotl이 처리합니다.

주요 기능:

- Llama, Pythia, Falcon, MPT 같은 인기 있는 오픈 웨이트 모델을 지원합니다.
- 유연한 학습 옵션: 전체 미세조정, LoRA, QLoRA, ReLoRA, GPTQ.
- xFormers, [FlashAttention](/kernel-optimization/flashattention/), ROPE
  스케일링, Liger 커널, 샘플 패킹(sample packing) 같은 고급 기법과 호환됩니다.
- 단일 GPU 구성부터 FSDP나 DeepSpeed를 사용하는 다중 GPU 학습까지 확장됩니다.
- Docker로 로컬에서 실행하거나 클라우드 인프라에서 쉽게 실행할 수 있습니다.

Axolotl은 심층 학습 내부의 세부 사항보다 데이터와 작업에 집중하고 싶은
사용자에게 잘 맞습니다. 합리적인 기본값, 탄탄한 커뮤니티 지원, 다양한 통합
기능을 갖추고 있어 오픈 모델을 실용적으로 미세조정할 때 우선 고려할 만한
선택지입니다.

### Unsloth {#unsloth}

[Unsloth](https://unsloth.ai/)는 LLM 학습을 더 빠르고, 더 가볍고, 더 접근하기
쉽게 만들도록 설계된 미세조정 프레임워크입니다. 특히 제한된 하드웨어(예: 무료
Google Colab GPU)에서 유용합니다.

Unsloth는 커널 수준에서 깊이 최적화되어 있습니다.
[Triton](https://openai.com/index/triton)으로 작성한 자체 어텐션 구현을 사용해
메모리 사용량을 최대 80% 줄이면서 학습 속도를 2× 높입니다. CUDA나 컴파일러 기반
접근 방식과 비교해 Triton이 어디에 위치하는지 더 알고 싶다면
[커널 최적화 도구](/kernel-optimization/kernel-optimization-tools/)를
참고하세요.

Unsloth 팀은 Llama 4, Mistral, Qwen, Gemma, Phi 같은 모델의 개발자들과 직접
협력해 왔습니다. 프롬프트 처리, 정확도, 전반적인 안정성을 개선하는 버그 수정과
업데이트에 자주 기여했습니다.

주요 기능:

- Llama, Mistral, Phi, Gemma 등 오픈 웨이트 모델의 미세조정을 지원합니다.
- LoRA, QLoRA, 전체 미세조정은 물론 강화학습(DPO, ORPO)까지 지원합니다.
- 높은 커스터마이징 자유도: 필요에 따라 채팅 템플릿, 데이터셋 형식, 학습 설정을
  수정할 수 있습니다.
- vLLM, SGLang, MAX 같은
  [추론 프레임워크](/getting-started/choosing-the-right-inference-framework/)와
  호환됩니다.
- Google Colab, Kaggle, 심지어 오래된 소비자용 GPU 같은 플랫폼에서도 쉽게
  실행됩니다.

자원이 제한된 환경에서 모델을 미세조정하려 한다면 Unsloth가 가장 먼저 고려할
만한 선택지입니다. 최소한의 자원으로 할 수 있는 일을 최대한 늘리도록
만들어졌습니다.

### Torchtune {#torchtune}

[Torchtune](https://github.com/pytorch/torchtune)은 LLM 미세조정을 위한 PyTorch
네이티브 라이브러리입니다. 고수준 추상화나 불투명한 학습 프레임워크에 의존하지
않고 학습 파이프라인을 완전히 제어하고 싶은 사용자를 위해 만들어졌습니다.

Torchtune은 PyTorch의 핵심 원칙인 "무엇보다 사용성"을 따릅니다. 불필요한
추상화를 피하고 다음을 강조합니다:

- 네이티브 PyTorch 구성 요소
- 상속보다 조합
- 숨겨진 프레임워크 동작 대신 명확한 학습 로직
- 모든 수준에서의 테스트 주도 개발과 정확성

주요 기능:

- 순수 PyTorch로 작성한 모듈식 LLM 구현.
- 전체 미세조정, LoRA, QLoRA 등 다양한 미세조정 기법을 위한 학습 레시피.
- 데이터셋, 모델, 하이퍼파라미터, 하드웨어 설정을 관리하는 YAML 파일 기반의 쉬운
  설정.
- 체크포인트 변환 도구를 통한 모델 저장소(model zoo)와의 상호 운용성.

PyTorch에서 직접 작업하면서 데이터 전처리부터 학습 로직까지 모든 것을
커스터마이징하고 싶다면 Torchtune이 이상적입니다. 투명한 코드, 재현성, 모델
내부에 대한 직접 접근을 중요하게 여기는 연구자, 개발자, 엔지니어에게 특히
유용합니다.

### LLaMA Factory {#llama-factory}

[LLaMA Factory](https://github.com/hiyouga/LLaMA-Factory)는 단순성과 효율성을
목표로 만든 오픈소스 미세조정 툴킷입니다. 100개가 넘는 LLM을 지원하며, 명령줄
인터페이스와 코드 없이 쓸 수 있는 워크플로용 Web UI를 모두 제공합니다.

전문 사용자를 대상으로 하는 많은 프레임워크와 달리, LLaMA Factory는 초보자도
쉽게 쓸 수 있도록 설계되었습니다. 웹 인터페이스에서 모델을 선택하고, 데이터셋을
업로드하고, 몇 가지 매개변수를 조정한 뒤 학습을 시작할 수 있습니다. 코딩은 전혀
필요 없습니다.

그렇다고 초보자만을 위한 도구는 아닙니다. LLaMA Factory는 내부적으로 다양한 튜닝
방법을 지원하므로 숙련된 연구자와 개발자에게도 똑같이 유용합니다.

주요 기능:

- 미세조정 방법: 지도 미세조정(SFT, 멀티모달 포함), 보상 모델링, 강화학습(PPO,
  DPO, ORPO, KTO).
- 양자화와 어댑터 지원: 16비트 전체 튜닝, 동결 튜닝(freeze-tuning), LoRA, 그리고
  GPTQ, AWQ, HQQ, AQLM 같은 형식을 통한 2–8비트 QLoRA.
- 고급 최적화: GaLore, DoRA, LongLoRA, LoftQ, LLaMA Pro, Mixture-of-Depths 등.

---

모델을 직접 미세조정하는 대신,
[Hugging Face](/getting-started/choosing-the-right-model/#hugging-face)에 있는
기존 미세조정 모델이나 지시 미세조정 모델로 시작할 수 있는 경우가 많습니다.
Hugging Face에는 커뮤니티와 공식 배포처가 공개한 미세조정 모델이 대량으로 있어
바로 사용할 수 있습니다. 동시에 완전한 제어권을 원하고 모델을 직접 미세조정할
계획이라면 베이스 모델과 파운데이션 체크포인트도 제공합니다. 실제로 많은 팀이
기존 모델을 재사용할지, 자체 미세조정에 투자할지 결정하기 전에 Hugging Face에서
두 가지 선택지를 모두 살펴봅니다.

## 호스팅 공급자를 통한 미세조정 {#fine-tuning-through-a-hosted-provider}

호스팅 공급자를 통한 미세조정은 학습 인프라를 직접 관리할 필요가 없어
편리합니다. 하지만 미세조정된 모델이 공급자와, 그 모델의 바탕이 된 베이스 모델에
의존하게 된다는 뜻이기도 합니다.

OpenAI의
[self-serve fine-tuning update](https://developers.openai.com/api/docs/deprecations#update-to-openais-self-serve-fine-tuning)가
좋은 예입니다. 2026년 5월 7일 이후로는 새 조직이 미세조정 작업을 만들 수
없습니다. 활성 상태인 기존 고객도 2027년 1월 6일까지만 새 작업을 만들 수
있습니다. 기존 미세조정된 모델은 베이스 모델이 지원 중단될 때까지 계속 실행할 수
있습니다.

그렇다고 호스팅 방식의 미세조정이 나쁜 선택이라는 뜻은 아닙니다. 팀이 호스팅된
미세조정 모델을 유지 관리가 필요한 프로덕션 산출물로 다뤄야 한다는 뜻입니다.
베이스 모델의 수명 주기를 추적하고, 교체 테스트에 쓸 평가 세트를 보관하세요.
필요할 때 다른 호스팅 모델이나 오픈소스 미세조정으로 옮겨 갈 수 있는지도 파악해
두세요.

## 자주 묻는 질문 {#faqs}

### 미세조정은 추론과 어떻게 다른가요? {#how-is-fine-tuning-different-from-inference}

미세조정은 작은 규모의 학습입니다. 자체 데이터셋을 사용해 모델 가중치의 일부를
업데이트합니다. 추론은 가중치를 전혀 바꾸지 않습니다. 기존 모델을 실행해 출력을
만들 뿐입니다.

두 가지를 더 명확하게 나란히 비교하면 다음과 같습니다:

| 항목            | 추론                       | 미세조정                                                 |
|-----------------|----------------------------|----------------------------------------------------------|
| 목적            | 출력 생성(답변, 이미지 등) | 특정 작업이나 도메인에서 더 나은 성능을 내도록 모델 조정 |
| 가중치 업데이트 | 없음, 가중치는 고정됨      | 있음, 가중치의 일부 또는 전부를 업데이트                 |
| 필요한 데이터   | 입력 프롬프트만            | 사용 사례에 맞는 데이터셋(대개 레이블 있음)              |
| 연산 비용       | 낮음(순전파 1회)           | 높음(여러 에포크의 학습)                                 |
| 시간            | 밀리초에서 몇 초           | 몇 분에서 며칠(모델 크기와 데이터에 따라 다름)           |
| 모델 변화       | 모델은 그대로 유지됨       | 모델의 새 버전/체크포인트를 얻음                         |
| 예시            | LLM에 질문하기             | 사내 문서나 의료 Q&A로 미세조정한 Llama 3                |

### LLM 미세조정은 프롬프트 엔지니어링 같은 다른 기법과 비교하면 어떤가요? {#how-does-llm-fine-tuning-compare-to-other-techniques-like-prompt-engineering}

[프롬프트 엔지니어링](/model-interaction/prompt-engineering/)은 더 나은 답변을
얻도록 모델에 질문하는 방식을 조정합니다. 빠르고 저렴하며 학습이 필요 없지만
한계가 있습니다. 프롬프트가 길어지면 지저분해질 수 있고, 모델이 여전히 일관성
없게 동작할 수도 있습니다.

미세조정은 모델 자체를 바꿉니다. "좋은" 결과가 어떤 모습인지 보여 주는 예시를
넣으면 모델이 그 패턴을 스스로 따르도록 학습합니다. 장기적으로 사용할 때 더
신뢰할 수 있으며, 특히 일관된 어조, 도메인 지식, 엄격한 형식이 필요할 때
그렇습니다.

요약하면 프롬프트 엔지니어링은 초기 탐색에 적합하고, 미세조정은 대규모에서
안정적이고 반복 가능한 성능을 제공합니다.

### 미세조정을 피해야 하는 경우는 언제인가요? {#when-should-i-avoid-fine-tuning}

주된 문제가 정보 부족이거나 정보가 자주 바뀌는 것이라면 미세조정을 피하세요.
이런 경우에는
[RAG 파이프라인](/infrastructure-and-operations/multi-model-inference-pipelines/#rag-pipeline),
프롬프트 템플릿, 도구 호출이 대개 더 적합합니다. 추론 시점에 최신 데이터를
가져올 수 있기 때문입니다.

신뢰할 수 있는 평가 세트가 없을 때도 미세조정은 첫 단계로 적절하지 않습니다.
평가 세트가 없으면 미세조정된 모델이 목표 동작을 실제로 개선했는지, 아니면
문체만 바뀌었는지 판단하기 어렵습니다.

마지막으로 배포 경로가 불확실하다면 미세조정을 피하세요. 미세조정된 모델은
베이스 모델, 학습 방법, 서빙 스택, 공급자의 수명 주기에 의존합니다. 곧 공급자나
베이스 모델을 바꿀 예정이라면 시스템이 안정될 때까지 더 많은 동작을 이식 가능한
런타임 로직에 두세요.

### LLM을 미세조정하려면 데이터가 얼마나 필요한가요? {#how-much-data-do-i-need-to-fine-tune-an-llm}

작업에 따라 다릅니다. 많은 팀이 수천 개의 고품질 예시로 좋은 결과를 얻습니다.
복잡한 도메인에서는 수만에서 수십만 개가 필요할 수도 있습니다. 양보다 질이 더
중요합니다.

### LLM을 미세조정하려면 고성능 GPU가 필요한가요? {#do-i-need-powerful-gpus-to-fine-tune-an-llm}

항상 그렇지는 않습니다. Unsloth, Axolotl, LLaMA Factory 같은 프레임워크는 LoRA와
QLoRA 같은 효율적인 방법을 지원합니다. 이런 방법을 쓰면 소비자용 GPU 한 장이나
Google Colab에서도 대형 모델을 미세조정할 수 있습니다. 전체 미세조정에는 대개 더
강력한 하드웨어가 필요합니다.
