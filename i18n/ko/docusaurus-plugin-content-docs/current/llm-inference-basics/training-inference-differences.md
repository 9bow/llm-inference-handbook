# 학습과 추론(training vs. inference)

LLM 학습과 추론은 모델 생애 주기에서 서로 다른 두 단계입니다.

<LLMLifecycleMap />

## 학습: 모델의 이해력을 쌓는 단계 {#training-building-the-models-understanding}

학습은 LLM을 처음 만들 때 이루어집니다. 학습의 목적은 모델이 패턴을 인식하고
정확하게 예측하도록 가르치는 것입니다. 이를 위해 모델에 방대한 데이터를 보여
주고, 모델이 접한 데이터를 바탕으로 매개변수를 조정합니다.

LLM 학습에 흔히 쓰이는 기법은 다음과 같습니다.

- **지도학습**: 입력과 올바른 출력을 짝지은 예시를 모델에 보여 줍니다.
- **강화학습**: 모델이 시행착오를 통해 배우게 하며, 피드백이나 보상을 바탕으로
  최적화합니다.
- **자기지도학습(self-supervised learning)**: 명시적인 레이블 없이 데이터에서
  빠지거나 손상된 부분을 예측하면서 학습합니다.

학습은 연산량이 많아 값비싼 GPU나 TPU 클러스터가 필요한 경우가 많습니다. 이 초기
비용은 매우 클 수 있지만 대체로 한 번만 드는 비용입니다. 모델이 원하는 정확도에
도달하고 나면, 보통은 주기적으로 모델을 갱신하거나 개선할 때만 재학습하면
됩니다.

## 추론: 모델을 실시간으로 사용하는 단계 {#inference-using-the-model-in-real-time}

LLM 추론은 학습된 모델을 새로운 데이터에 적용해 예측하는 것을 말합니다. 학습과
달리 추론은
[지속적으로, 실시간으로 이루어지며](/llm-inference-basics/what-is-llm-inference/)
사용자 입력이나 들어오는 데이터에 즉시 응답합니다. 추론은 모델이 실제로
"사용되는" 단계입니다. 더 잘 학습되고 더 정교하게 미세조정된 모델일수록 대체로
더 정확하고 유용한 추론 결과를 냅니다.

추론에 필요한 연산은 계속 발생하며, 특히 사용자 상호작용과 트래픽이 늘어날수록
매우 커질 수 있습니다. 추론 요청 하나하나가 GPU 같은 연산 자원을 소비합니다.
추론 단계 하나만 놓고 보면 학습보다 작을 수 있지만, 시간이 지나며 누적되는
수요는 상당한 운영 비용으로 이어질 수 있습니다.

---

학습과 추론을 나란히 비교하면 다음과 같습니다.

| 항목      | 학습                              | 추론                                          |
|-----------|-----------------------------------|-----------------------------------------------|
| 목적      | 모델을 가르침                     | 모델을 사용함                                 |
| 데이터    | 대규모 데이터셋                   | 사용자가 제공하는 새로운 입력                 |
| 연산      | 길고 비용이 큰 GPU/TPU 작업       | 실시간으로 반복되는 워크로드                  |
| 비용 구조 | 대부분 일회성                     | 지속적으로 발생하며 트래픽에 따라 증가        |
| 하드웨어  | 멀티 노드 클러스터                | 더 작은 클러스터, 최적화된 런타임과 캐시 활용 |
| 소요 시간 | 수 시간에서 수 주                 | 수 밀리초에서 수 초                           |
| 도구      | PyTorch, JAX, DeepSpeed, Megatron | vLLM, SGLang, TensorRT LLM, MAX, LMDeploy     |

## 자주 묻는 질문 {#faqs}

### 모델 서빙이란 무엇인가요? {#what-is-model-serving}

모델 서빙은 학습된 모델을 애플리케이션, 사용자, 시스템이 쓸 수 있게 만들어
새로운 입력에 대해 추론을 실행할 수 있도록 하는 프로덕션 과정입니다. 보통 모델을
패키징하고, 적합한 하드웨어에 로드하고, API나 서비스로 노출하고, 동작을
모니터링하고, 지연 시간·신뢰성·보안·비용을 관리하는 일이 포함됩니다.

[서빙과 추론](/llm-inference-basics/what-is-llm-inference/#whats-the-difference-between-serving-and-inference)의
차이를 자세히 알아보세요.

### LLM 생애 주기에서 학습과 추론은 어디에 위치하나요? {#where-do-training-and-inference-fit-in-the-llm-lifecycle}

학습은 생애 주기 초기에 이루어집니다. 이 단계에서 모델은 패턴, 언어 구조, 일반
지식을 배웁니다. 그다음 모델은 정렬(alignment), 선택적인 미세조정, 평가, 배포를
거칩니다. 추론은 배포 이후에 이루어집니다. 추론은 모델이 프로덕션에서 실제
사용자에게 서비스하는 단계이며, 보통 API, 서비스, 애플리케이션 워크플로를 통해
이루어집니다. 학습은 "모델을 만드는 일", 추론은 "모델을 일하게 하는 일"이라고
생각하면 됩니다.

### LLM 추론 비용이 학습보다 더 많이 드는 경우가 많은 이유는 무엇인가요? {#why-does-llm-inference-often-cost-more-than-training}

LLM 학습은 비용이 많이 들지만 보통 한 번만 이루어집니다. 반면 추론은 사용자가
요청을 보낼 때마다 실행됩니다. 트래픽이 늘면 추론 호출 횟수도 함께 늘어납니다.
요청마다 GPU 연산, 메모리, 네트워크 대역폭을 사용합니다. 시간이 지나면 이렇게
계속되는 수요 때문에 장기적으로는 추론 비용이 더 커질 수 있습니다. 사용량이
많거나 [프롬프트](/model-interaction/prompt-engineering/)가 긴
애플리케이션에서는 특히 그렇습니다.

### LLM을 직접 학습해야 하나요? {#should-i-train-my-own-llm}

대부분의 경우 그럴 필요가 없습니다. 새로운 LLM을 처음부터 학습하려면 방대한
데이터셋, 특수 하드웨어, 전담 연구팀이 필요합니다. 대부분의 기업은 기존
[오픈소스 LLM](/getting-started/choosing-the-right-model/)에서 시작해 자기
도메인에 맞게 미세조정하거나 커스터마이즈하는 편이 더 좋은 결과를 얻습니다.
처음부터 전체 학습을 하는 것은 기존 모델로 해결할 수 없는 문제를 풀어야 하거나,
미세조정으로는 충족할 수 없는 엄격한 통제 요구 사항이 있을 때만 의미가 있습니다.

### 미세조정은 학습인가요, 추론인가요? {#is-fine-tuning-considered-training-or-inference}

미세조정은 학습의 한 형태입니다. 새로운 데이터로 모델 가중치 일부를 갱신해
모델을 특정 작업이나 도메인에 맞춥니다. 추론은 가중치를 전혀 바꾸지 않으며,
모델을 사용해 예측을 생성하기만 합니다. 자세한 내용은
[미세조정 섹션](/model-preparation/llm-fine-tuning/)을 참고하세요.
