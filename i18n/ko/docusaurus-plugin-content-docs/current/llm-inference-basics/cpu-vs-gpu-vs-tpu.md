# LLM 추론은 어디에서 실행되나요?

LLM을 프로덕션에 배포할 때는 적합한 하드웨어를 고르는 것이 매우 중요합니다.
하드웨어 유형마다 성능과 비용 효율성 수준이 다릅니다. 주요 선택지는 CPU, GPU,
TPU 세 가지입니다. 각각의 강점과 약점을 이해하면 추론 워크로드를 효과적으로
최적화할 수 있습니다.

## CPU {#cpus}

중앙 처리 장치(Central Processing Unit, CPU)는 모든 컴퓨터와 서버에 쓰이는 범용
프로세서입니다. CPU는 쉽게 구할 수 있으며, 작은 모델을 실행하거나 드문드문
들어오는 요청을 처리하기에 적합합니다. 하지만 LLM을 효율적으로 실행할 만한 병렬
처리 능력은 부족합니다. 프로덕션 수준의 LLM 추론, 특히 큰 모델이나 많은 요청을
다룰 때 CPU는 지연 시간과 처리량 모두에서 부족한 경우가 많습니다.

## GPU {#gpus}

그래픽 처리 장치(Graphics Processing Unit, GPU)는 원래 그래픽 렌더링과 디지털
시각화 작업을 위해 설계되었습니다. GPU는 고도로 병렬화된 연산을 수행할 수 있어서
ML과 AI 워크로드에도 아주 잘 맞는 것으로 드러났습니다. 오늘날 GPU는 LLM 같은
생성형 AI(GenAI)의 학습과 추론 모두에서 기본 선택지입니다.

[GPU 아키텍처](/kernel-optimization/gpu-architecture-fundamentals/)는 트랜스포머
기반 모델의 핵심 구성 요소인 행렬 곱과 텐서 연산에 최적화되어 있습니다. 최신
추론 프레임워크와 런타임(예: vLLM, SGLang, MAX, LMDeploy, TensorRT LLM, Hugging
Face TGI)은 GPU 가속을 최대한 활용하도록 설계되었습니다.

## TPU {#tpus}

텐서 처리 장치(Tensor Processing Unit, TPU)는 학습과 추론 같은 AI 워크로드를
가속하기 위해 Google이 자체 설계한 프로세서입니다. GPU와 비교하면 TPU는 신경망의
기본 수학 연산인 텐서 연산을 위해 처음부터 설계되었습니다. 이러한 특화 덕분에
TPU는 LLM 추론처럼 AI 기반의 여러 연산 작업에서 GPU보다 빠르고 효율적입니다.

TPU는 에이전트, 추천 시스템과 개인화, 이미지·비디오·오디오 합성 등 오늘날 가장
앞선 AI 애플리케이션 일부를 뒷받침합니다. Google은 검색(Search), 포토(Photos),
지도(Maps)에 TPU를 사용하며, Gemini와 DeepMind 모델 구동에도 TPU를 사용합니다.

---

다음은 세 가지 하드웨어를 나란히 비교한 표입니다.

| 항목                  | CPU                                               | GPU                                                        | TPU                                      |
|-----------------------|---------------------------------------------------|------------------------------------------------------------|------------------------------------------|
| **설계 목적**         | 범용 컴퓨팅                                       | 그래픽과 심층 학습을 위한 병렬 컴퓨팅                      | 밀집 텐서 연산에 최적화                  |
| **핵심 강점**         | 유연성, 다양한 유형의 작업 처리                   | 대규모 병렬성, 학습과 추론에 탁월                          | 텐서 연산에서 매우 높은 효율             |
| **병렬성**            | 낮음                                              | 높음                                                       | 매우 높음                                |
| **적합한 용도**       | 분기 로직, 소규모 워크로드, 전통적인 애플리케이션 | LLM, 이미지 모델 학습 및 서빙, 비디오 작업                 | 대규모 학습과 고처리량 추론              |
| **메모리 유형**       | DRAM                                              | GDDR / HBM                                                 | HBM                                      |
| **메모리 대역폭**     | 낮음                                              | 높음                                                       | 매우 높음                                |
| **지연 시간**         | 코어당 지연 시간이 낮음                           | 지연 시간은 더 높지만 병렬성으로 상쇄                      | 행렬 연산에서 지연 시간이 낮음           |
| **전력 효율**         | 보통                                              | 보통에서 높음                                              | ML 워크로드에서 매우 높음                |
| **소프트웨어 생태계** | 성숙하고 보편적                                   | CUDA, ROCm, PyTorch, TensorFlow                            | XLA, JAX, TensorFlow                     |
| **비용**              | 낮음                                              | 중간에서 높음                                              | 높음, 주로 클라우드를 통해 이용 가능     |
| **확장성**            | 심층 학습에서는 제한적                            | 멀티 GPU 구성에서 잘 확장됨, LLM은 콜드 스타트 문제가 있음 | TPU 포드에서 확장성이 뛰어남             |
| **사용 사례**         | 데이터 전처리, 백엔드 서비스, 작은 로컬 모델 실행 | LLM 학습과 추론                                            | 대규모 배치 학습, Google의 프로덕션 추론 |

## LLM 추론에 적합한 하드웨어 선택하기 {#choosing-the-right-hardware-for-your-llm-inference}

적절한 하드웨어를 고르려면 모델 크기, 추론량, 지연 시간 요구 사항, 비용 제약,
사용 가능한 인프라를 파악해야 합니다. GPU는 범용성과 폭넓은 지원 덕분에 여전히
가장 많이 선택되는 하드웨어입니다. TPU는 일부 특수한 시나리오에서 뚜렷한 이점을
제공하며, CPU도 가볍고 예산을 중시하는 워크로드에서는 여전히 쓸모가 있습니다.

다양한 오픈소스 LLM에 맞는
[GPU 선택](/getting-started/choosing-the-right-gpu/)에 대해 더 알아보세요.

## 적합한 배포 패턴 선택하기 {#choosing-the-right-deployment-pattern}

배포 패턴은 지연 시간과 확장성부터 개인정보 보호와 비용까지 모든 것을
좌우합니다. 패턴마다 기업의 서로 다른 운영 요구에 맞습니다.

- **클라우드**: 클라우드는 오늘날 LLM 추론에 가장 많이 쓰이는 환경입니다. 고성능
  GPU와 TPU를 필요할 때 바로 사용할 수 있고, 관리형 서비스, 오토스케일링,
  모니터링 도구로 이루어진 풍부한 생태계도 함께 제공합니다.
- **멀티 클라우드 및 리전 간**:
  [이 유연한 배포 전략](/infrastructure-and-operations/multi-cloud-and-cross-region-inference/)은
  LLM 워크로드를 여러 클라우드 공급자나 지리적 리전에 분산합니다. 전 세계
  사용자의 지연 시간을 줄이고, GPU 가용성을 높이고, 컴퓨팅 비용을 최적화하고,
  벤더 종속을 완화하며, 데이터 상주(data residency) 요건 준수를 지원합니다.
- **BYOC(Bring Your Own Cloud)**:
  [BYOC 배포](/getting-started/bring-your-own-cloud/)를 사용하면 LLM 추론 플랫폼
  같은 벤더 소프트웨어를 자체 클라우드 계정 안에서 직접 실행할 수 있습니다. 이
  모델은 관리형 오케스트레이션과 데이터, 네트워크, 비용에 대한 완전한 통제를
  결합합니다. 완전한 셀프 호스팅 없이도 규정 준수, 비용 효율성, 확장성이 필요한
  기업에 이상적입니다.
- **온프레미스**: [온프레미스 배포](/getting-started/on-prem-llms/)는 일반적으로
  프라이빗 데이터 센터 안에서 자체 인프라로 LLM 추론을 실행하는 것을 말합니다.
  이 패턴은 데이터, 성능, 규정 준수를 완전히 통제할 수 있지만 운영 부담이 더
  큽니다.
- **엣지**: 엣지 배포에서는 데이터가 생성되는 곳과 가까운 사용자 기기나 로컬
  엣지 노드에서 모델을 직접 실행합니다. 이렇게 하면 네트워크 지연 시간이 줄고
  데이터 프라이버시가 높아지며, 특히 시간에 민감하거나 오프라인 환경의 사용
  사례에 유리합니다. 엣지 추론은 컴퓨팅 자원이 제한적이기 때문에 보통 더 작고
  최적화된 모델을 사용합니다.
