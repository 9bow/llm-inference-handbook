# 적합한 모델 선택하기

AI 애플리케이션을 만들 때 가장 먼저 내려야 하는 결정 가운데 하나가 적합한 LLM을
고르는 일입니다.

모델마다 설계된 목적이 다릅니다. 텍스트 생성을 위해 학습된 모델도 있고, 지시를
따르도록 최적화된 모델도 있으며, 효율성이나 멀티모달 작업에 초점을 둔 모델도
있습니다.

## 베이스 모델이란? {#what-are-base-models}

베이스 모델(base model)은 파운데이션 모델(foundation model)이라고도 하며, 대부분
LLM의 출발점입니다. 베이스 모델은 보통 방대한 텍스트 말뭉치로
비지도학습(unsupervised learning)을 거쳐 학습되며, 이 방식에는 레이블이 붙은
데이터가 필요하지 않습니다.

사전학습(pretraining)이라고 부르는 이 초기 단계에서 모델은 문법, 구문, 의미,
맥락 같은 일반적인 언어 패턴을 익힙니다. 그 결과 다음 단어(또는 토큰)를 예측할
수 있게 되고, 간단한 퓨샷 학습(few-shot learning), 즉 예시를 몇 개만 보고 작업을
처리하는 일도 할 수 있습니다. 하지만 아직 지시를 따르는 방법은 알지 못하며,
그대로는 특정 작업에 최적화되어 있지 않습니다.

베이스 모델을 쓸모 있게 만들려면 보통 선별된 데이터셋으로 지시
미세조정(instruction fine-tuning) 같은 기법을 써서 미세조정을 거칩니다. 베이스
모델에서 만들 수 있는 모델은 다음과 같습니다.

- 지시 미세조정된 모델
- 채팅 모델
- 도메인별로 미세조정된 모델
- RLHF로 정렬된 모델

베이스 모델 예시: Qwen3.5-0.8B-Base, DeepSeek-V3-Base, GPT 계열 사전학습 모델

## 지시 미세조정된 모델과 채팅 모델 {#instruction-tuned-vs-chat-models}

지시 미세조정된 모델(instruction-tuned model)은 베이스 모델을 바탕으로
만들어집니다. 초기 사전학습 단계를 마친 뒤, 지시와 그에 대응하는 응답으로 구성된
데이터셋으로 두 번째 학습 단계를 거칩니다.

이 과정을 거치면 모델은 사용자의
[프롬프트](/model-interaction/prompt-engineering/)를 더 안정적으로 따르게 되어
사람의 기대에 더 잘 맞춰집니다. 작업 의도를 이해하고, 다음과 같은 명령에 더
일관되게 응답합니다.

- “이 기사를 요약해 줘.”
- “LLM 추론이 어떻게 동작하는지 설명해 줘.”
- “재택근무의 장단점을 나열해 줘.”

그래서 지시 미세조정된 모델은 챗봇, 가상 비서, 사용자와 직접 상호작용하는 AI
도구 같은 실제 애플리케이션에 더 실용적입니다.

LLM 이름에 “Instruct”가 들어 있다면 대개 지시 미세조정된 모델이라는 뜻입니다.
하지만 “Instruct” 모델이 반드시 완전한 챗봇인 것은 아닙니다. 주어진 작업을
완료하거나 지시를 따르도록 최적화되어 있을 뿐, 여러 턴에 걸친 대화를 이어 가도록
최적화되어 있지는 않습니다.

반면 채팅 모델은 보통 대화 데이터와 RLHF/DPO 등으로 한 번 더 조정되어,
상호작용하는 챗봇 시나리오에서 좋은 성능을 내도록 만들어집니다. 채팅 모델은 여러
턴에 걸친 맥락을 다루고 여러 참여자와 상호작용할 수 있어야 합니다. 자세한 내용은
[Instruction and Chat Fine-Tuning](https://builder.aws.com/content/2ZVa61RxToXUFzcuY8Hbut6L150/what-is-an-instruct-model-instruction-and-chat-fine-tuning)을
참고하세요.

Instruct 모델 예시: Meta-Llama-3-8B-Instruct, Qwen3-4B-Instruct-2507,
Kimi-K2-Instruct-0905

## 밀집 모델과 전문가 혼합(MoE) 모델 {#dense-models-vs-mixture-of-experts-moe-models}

전통적인 LLM은 대부분 밀집 모델(dense model)입니다. 즉, 추론 중에 모든 토큰마다
네트워크의 모든 매개변수를 사용합니다.

[DeepSeek-V4 Pro](https://www.modular.com/models/deepseek-v4-pro) 같은 전문가
혼합(MoE) 모델은 전통적인 밀집 모델과 다른 방식을 취합니다. 모든 입력에 모델의
매개변수 전체를 쓰는 대신, **전문가**(expert)라고 부르는 여러 전문화된 하위
네트워크를 두고, 각 전문가가 서로 다른 유형의 데이터나 작업에 집중합니다.

추론 중에는 입력의 특성에 따라 전문가 가운데 일부만 활성화됩니다. 이 선택
메커니즘 덕분에 모델은 연산을 더 선별적으로 라우팅하여, 내용이나 맥락에 따라
서로 다른 전문가를 사용할 수 있습니다. 그 결과 MoE 모델은 워크로드를 큰 네트워크
전체에 분산하면서도 추론 한 번당 연산 비용을 감당할 만한 수준으로 유지하여, 더
높은 확장성과 효율을 얻습니다.

| 모델 유형 | 동작 방식                  | 장점            | 단점                 |
|-----------|----------------------------|-----------------|----------------------|
| 밀집      | 모든 매개변수 사용         | 단순한 아키텍처 | 대규모에서 비용이 큼 |
| MoE       | 전문가를 선택적으로 활성화 | 효율적인 확장   | 더 복잡한 라우팅     |

## LLM과 다른 모델 결합하기 {#combining-llms-with-other-models}

현대 AI 애플리케이션이 LLM 하나만 쓰는 경우는 드뭅니다. 많은 고급 시스템은 LLM을
다른 유형의 모델과 조합하며, 각 모델은 서로 다른 모달리티나 작업에 특화되어
있습니다. 이렇게 하면 단순한 텍스트 생성을 넘어 더 유능하고, 멀티모달을 다루며,
작업을 인식하는 시스템이 됩니다.

흔한 예는 다음과 같습니다.

- **소형 언어 모델(SLM)**. 지연 시간과 자원 제약이 중요한 가벼운 작업에
  쓰입니다. 전체 LLM에 의존하지 않고 기본적인 상호작용을 처리하는 대체(fallback)
  모델이나 온디바이스 비서 역할을 할 수 있습니다.
- **임베딩 모델**. 텍스트나 이미지 같은 입력을 벡터 표현으로 바꾸므로, 시맨틱
  검색, RAG 파이프라인, 추천 시스템, 클러스터링에 유용합니다.
- **이미지 생성 모델**. Stable Diffusion 같은 모델은 텍스트 프롬프트로 이미지를
  생성합니다. LLM과 함께 쓰면 창작 보조 도구, 콘텐츠 생성기, 멀티모달 에이전트
  같은 더 발전된 텍스트-이미지 워크플로를 지원할 수 있습니다.
- **비전-언어 모델(VLM)**. NVLM 1.0과 Qwen2.5-VL 같은 모델은 시각 이해와 텍스트
  이해를 결합하여, 이미지 캡션 생성, 시각 질의응답, 스크린샷과 다이어그램에 대한
  추론 같은 작업을 지원합니다.
- **텍스트 음성 변환(TTS) 모델**. 텍스트를 자연스러운 음성으로 변환할 수
  있습니다. LLM과 통합하면 음성 기반 에이전트, 접근성 인터페이스, 몰입형 경험에
  쓸 수 있습니다.

[멀티 모델 추론 파이프라인](/infrastructure-and-operations/multi-model-inference-pipelines/)에
대해 더 알아보세요.

## 모델을 구하는 곳 {#where-to-get-models}

어떤 종류의 모델이 필요한지 알았다면, 다음 질문은 간단합니다. 실제로 그런 모델은
어디서 찾을 수 있을까요?

오늘날 대부분의 팀은 모델을 처음부터 학습하지 않습니다. 공개 모델 허브에서
모델을 가져와 조정한 뒤 배포합니다.

### Hugging Face {#hugging-face}

[Hugging Face](https://huggingface.co/models)는 대부분의 팀에게 기본
출발점입니다. 텍스트, 비전, 오디오, 멀티모달 작업에 걸쳐 수십만 개의 공개 모델을
호스팅합니다. 이곳에서 베이스 모델, Instruct 모델, 채팅 변형, 임베딩 모델, 확산
모델을 찾을 수 있습니다. Hugging Face는
[미세조정된](/model-preparation/llm-fine-tuning/) 변형과
[양자화된 모델](/model-preparation/llm-quantization/) 변형도 많이 제공하므로,
직접 미세조정하지 않고도 지시 미세조정된 모델이나 적은 VRAM으로 돌아가는 모델을
쉽게 실험해 볼 수 있습니다.

많이 쓰이는 이유는 다음과 같습니다.

- 거대한 생태계와 폭넓은 커뮤니티 채택
- 라이선스, 벤치마크, 의도된 용도를 담은 명확한 모델 카드
- 대부분의 추론 프레임워크(예: vLLM, SGLang, MAX, TensorRT LLM)에서 기본 지원
- 가중치, 설정 파일, 토크나이저에 쉽게 접근 가능

**Hugging Face의 모든 모델에 똑같이 접근할 수 있는 것은 아니라는 점**에
유의하세요. 어떤 모델은 완전히 공개되어 있어 인증 없이 내려받을 수 있습니다.
다른 모델은 접근이 제한(gated)되어 있어, 특정 라이선스 조건에 동의하고
[Hugging Face API 토큰](https://huggingface.co/docs/hub/en/security-tokens)을
사용해야 가중치에 접근할 수 있습니다.

이런 제한은 보통 다음과 같은 경우에 걸립니다.

- 모델에 제한적이거나 자체적인 라이선스가 적용된 경우
- 작성자가 누가 모델을 사용하는지 파악하고 싶은 경우
- 모델이 연구용이나 통제된 상업적 용도로 공개된 경우

실제로는 다음 작업이 필요할 수 있습니다.

- Hugging Face 계정 만들기
- API 토큰 발급하기
- 발급한 토큰을
  [추론 프레임워크](/getting-started/choosing-the-right-inference-framework/)나
  배포 환경에 전달하기(예: `HF_TOKEN` 같은 환경 변수 사용)

접근이 제한된 모델은 사용 조건이 더 엄격하거나, 운영 측면의 완성도가 떨어지거나,
장기적인 가용성에 대한 보장이 약한 경우가 많습니다.

간단한 경험칙은 다음과 같습니다. 모델에 토큰과 수동 승인이 필요하다면, 그 모델을
바탕으로 무언가를 만들기 전에 프로덕션 및 법적 제약에 맞는지 다시 확인하세요.

그 밖에 주의할 점은 다음과 같습니다.

- 라이선스 차이(Apache-2.0, MIT, 자체 라이선스)
- 매개변수 수 뒤에 가려진 VRAM 요구 사항
- 일부 모델은 연구용 수준이며 프로덕션에 바로 쓸 수 있는 상태가 아님

테스트하기 전에 항상 모델 카드를 읽으세요. 모델 카드를 보면 그 모델이 실제로
무엇을 잘하고 무엇을 못하는지 알 수 있습니다.

### ModelScope {#modelscope}

[ModelScope](https://www.modelscope.cn/models)는 Alibaba가 운영하는 주요 공개
모델 허브입니다. 특히 다음 분야의 모델을 폭넓게 갖추고 있습니다.

- 중국어 및 다국어 LLM
- 비전-언어 모델
- 음성 및 멀티모달 모델
- 로컬 및 지역 사용 사례에 최적화된 모델

중국어 사용자를 위한 제품을 만들거나, Hugging Face 접근이 느리거나 제한될 수
있는 지역에 배포하는 팀이라면 ModelScope를 가장 먼저 살펴보는 경우가 많습니다.
이곳에 공개된 모델 상당수가 결국 Hugging Face에도 올라오지만, 일부는 한동안
ModelScope에 먼저 올라오거나 ModelScope에만 남아 있기도 합니다.

### OpenRouter {#openrouter}

[OpenRouter](https://openrouter.ai/)는 전통적인 “모델 허브”라기보다는 모델 접근
계층에 가깝습니다.

가중치를 내려받아 직접 모델을 실행하는 대신, OpenRouter로 다음과 같은 일을 할 수
있습니다.

- 단일 API로 많은 공개 모델과 독점 모델에 접근
- 모델 간 동작, 지연 시간, 비용 비교
- 모델 간에 트래픽을 동적으로 라우팅

이 방식은 초기 단계의 프로토타이핑, A/B 테스트, 셀프 호스팅을 확정하기 전의 모델
평가에 유용합니다. 하지만 대규모 환경에서 성능, 데이터, 비용을 엄격하게 통제해야
한다면 자체 추론 스택을 운영하는 것을 대신할 수는 없습니다.

## 모델 가중치 형식 {#model-weight-formats}

오픈소스 LLM을 내려받는다는 것은 보통 그 모델의 가중치를 내려받는다는 뜻입니다.
모델 가중치는 학습 중에 얻은 지식을 저장하는 학습된 매개변수입니다. 가중치는
보통 추론 프레임워크가 불러올 수 있는 파일 형태로 배포됩니다.

LLM 생태계에서 흔히 쓰이는 가중치 형식은 여러 가지가 있습니다.

### PyTorch 체크포인트 {#pytorch-checkpoints}

많은 모델이 처음에는 PyTorch 체크포인트 파일로 공개되며, 파일 확장자는 보통
다음과 같습니다.

```bash
pytorch_model.bin
model.pt
```

이 파일들은 PyTorch가 바로 불러올 수 있는 직렬화된 형식으로 모델 매개변수를
저장합니다. 하지만 전통적인 체크포인트 형식에는 몇 가지 단점이 있습니다.

- 불러오는 속도가 느릴 수 있습니다
- 역직렬화 단계가 필요할 수 있습니다
- 일부 형식은 임의 코드 실행을 허용하므로 보안 우려가 있습니다

이런 한계 때문에 최근 공개되는 모델 상당수는 더 안전한 대안을 사용합니다.

### Safetensors {#safetensors}

Safetensors는 현재 LLM 가중치 배포에 가장 널리 쓰이는 형식 가운데 하나입니다.
Hugging Face가 PyTorch 체크포인트를 대체할 안전하고 빠른 형식으로 도입했습니다.

주요 특징은 다음과 같습니다.

- 임의 코드 실행을 막아 안전하게 불러올 수 있음
- 빠른 메모리 매핑으로 가중치를 효율적으로 불러올 수 있음
- vLLM, TensorRT LLM, SGLang, MAX 같은 추론 프레임워크에서 폭넓게 지원

예시 파일:

```bash
model-00001-of-00004.safetensors
model-00002-of-00004.safetensors
model-00003-of-00004.safetensors
model-00004-of-00004.safetensors
```

큰 모델은 내려받고 관리하기 쉽도록 여러 파일로 샤딩(sharding)되는 경우가
많습니다.

모델이 여러 safetensors 샤드로 배포되면 `model.safetensors.index.json`이라는
파일을 흔히 볼 수 있습니다. 이 파일은 각 매개변수 텐서가 어디에 저장되어 있는지
로더에 알려 주는 매핑 인덱스 역할을 합니다. 대부분의 사용자에게는 추론
프레임워크가 이 과정을 자동으로 처리해 줍니다. 그래도 인덱스 파일을 이해해 두면
다음과 같은 경우에 도움이 됩니다.

- 모델 로딩 문제 디버깅
- 모델 가중치 수정
- 사용자 정의 체크포인트 작업

### GGUF {#gguf}

GGUF는 효율적인 로컬 추론, 특히 llama.cpp 같은 도구에서의 추론을 위해 설계된
모델 형식입니다. GGUF 모델은 보통 다음과 같은 특징이 있습니다.

- 메모리 사용량을 줄이기 위해 양자화되어 있음
- CPU나 소형 GPU 환경에 최적화되어 있음
- 모델을 로컬에서 실행할 때 많이 쓰임

예시 파일:

```bash
model.Q4_K_M.gguf
```

양자화 유형(Q4, Q5, Q8 등)은 모델 가중치를 얼마나 공격적으로 압축했는지를
나타냅니다.

## 자주 묻는 질문 {#faqs}

### 베이스 모델과 Instruct 모델의 차이는 무엇인가요? {#what-is-the-difference-between-base-and-instruct-models}

베이스 모델은 원시 텍스트로 사전학습되어 언어 패턴을 익힌 모델입니다. Instruct
모델은 프롬프트를 따르고 작업을 완료하도록 미세조정된 모델입니다.

### LLM 이름 규칙은 어떻게 읽나요? {#how-to-understand-llm-naming-conventions}

일부 LLM은 이름이 길고 헷갈리지만, 보통 그 안에 모델의 아키텍처, 크기, 기능에
대한 유용한 정보가 담겨 있습니다. 이름 읽는 법을 알고 나면 모델을 비교하고
적합한 모델을 고르기가 훨씬 쉬워집니다.

<figure>
  <Diagram name="llm-naming" alt="" />
  <figcaption><b>그림 1.</b> LLM 이름의 구성.</figcaption>
</figure>

- 숫자는 보통 모델의 매개변수 수를 나타냅니다. 문자 B는 10억(billion) 개의
  매개변수를 뜻합니다.
- “Instruct”는 모델이 지시 미세조정되었다는 뜻입니다. “Chat” 모델은 여러 턴에
  걸친 대화에 최적화되어 있습니다.
- 일부 모델에는 [“양자화된” 버전](/model-preparation/llm-quantization/)이
  있으며, 이는 메모리 사용량을 줄이기 위해 모델 가중치를 압축했다는 뜻입니다.
- 일부 모델 이름에는 연도, 월, 날짜가 들어가 모델이 공개되거나 업데이트된 시점을
  나타냅니다. 사용자는 이를 보고 모델의 세대를 빠르게 파악할 수 있습니다.
- MoE 모델은 Qwen3.5-35B-A3B처럼 이름에 숫자 두 개를 넣어 전문가 시스템의 동작
  방식을 나타내기도 합니다. 이 숫자들은 보통 다음을 뜻합니다.
  - 전체 전문가 수
  - 추론 중에 활성화되는 전문가 수
