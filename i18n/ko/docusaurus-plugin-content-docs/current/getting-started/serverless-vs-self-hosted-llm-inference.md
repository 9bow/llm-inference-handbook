# 서버리스 vs. 셀프 호스팅 LLM 추론

LLM으로 애플리케이션을 만들 때는 보통 두 가지 주요 인프라 선택지가 있습니다.
바로 **서버리스**(관리형 API)와 **셀프 호스팅** 솔루션입니다. 두 선택지는 비교를
위한 양 끝점으로 유용하지만, 실제 프로덕션 배포는 그 사이 어디에든 위치할 수
있습니다. 각 방식은 사용 편의성, 커스터마이징, 확장성, 규정 준수 측면에서 서로
다른 트레이드오프를 가집니다.

## 서버리스 LLM 추론 {#serverless-llm-inference}

OpenAI, Anthropic 및 기타 호스팅 API 공급자가 제공하는 서버리스 추론 서비스는
애플리케이션 개발을 크게 단순화합니다. 이러한 서비스는 모든 것을 대신 관리해
주므로, 인프라 부담 없이 사용한 만큼만 비용을 지불하면 됩니다.

이러한 서비스는 GPT-5나 Claude-Sonnet-4.5 같은 독점 모델만으로 운영되지
않습니다. DeepSeek-R1, Llama 4 같은 오픈소스 모델도 Together AI, Fireworks 같은
플랫폼에서 서버리스 엔드포인트로 사용할 수 있습니다.

서버리스 API의 주요 장점은 다음과 같습니다.

- **사용 편의성**: 최소한의 설정으로 빠르게 시작할 수 있습니다. API 키와 몇 줄의
  코드만 있으면 됩니다. 하드웨어, 소프트웨어 환경, 복잡한 확장 로직을 관리할
  필요가 없습니다.
- **빠른 프로토타이핑**: 인프라 부담 없이 아이디어를 빠르게 테스트하거나, 데모나
  내부 도구를 만드는 데 안성맞춤입니다.
- **하드웨어 추상화**: LLM을 대규모로 셀프 호스팅하려면 보통 고성능 GPU(NVIDIA
  A100이나 H100 등)가 필요합니다. 서버리스 API는 이러한 하드웨어의 복잡성을
  추상화하므로, GPU 부족, 할당량 제한, 프로비저닝 지연을 피할 수 있습니다.

## 셀프 호스팅 LLM 추론 {#self-hosted-llm-inference}

셀프 호스팅 LLM 추론이란 클라우드 GPU, 프라이빗 VPC, 온프레미스 서버 중 무엇을
쓰든 자체
[LLM 인프라](/infrastructure-and-operations/what-is-llm-inference-infrastructure/)를
배포하고 관리하는 것을 말합니다. 애플리케이션 요구 사항에 맞게 모델을 배포하고,
최적화하고, 확장하는 방식을 직접 제어합니다.

셀프 호스팅의 주요 이점은 다음과 같습니다.

- **데이터 프라이버시와 규정 준수**: LLM은 RAG, AI 에이전트 같은 현대
  애플리케이션에서 널리 쓰입니다. 이러한 시스템은 민감한 데이터(예: 고객 정보,
  의료 기록, 금융 정보)에 자주 접근해야 하는 경우가 많습니다. 규정 준수와
  프라이버시 요구 사항이 있는 규제 산업의 조직에게 서버리스 API는 받아들일 수
  없는 선택지일 때가 많습니다. LLM을 셀프 호스팅하면 데이터가 항상 안전한 자체
  환경 안에 머무릅니다.
- **고급 커스터마이징과 최적화**: 셀프 호스팅을 하면 다음과 같이 특정 요구에
  맞게 추론 과정을 조정할 수 있습니다.
  - 지연 시간과 처리량 사이의 트레이드오프를 정밀하게 조정합니다.
  - [프리필-디코드 분리](/inference-optimization/prefill-decode-disaggregation/),
    [프리픽스 캐싱](/inference-optimization/prefix-caching/),
    [추측 디코딩](/inference-optimization/speculative-decoding/) 같은 고급
    최적화를 구현합니다.
  - 긴 컨텍스트나
    [배칭](/inference-optimization/static-dynamic-continuous-batching/)
    시나리오에 맞게 최적화합니다.
  - 구조화된 디코딩을 강제하여 출력이 엄격한 스키마를 따르도록 합니다.
  - 독점 데이터로 [모델을 미세조정](/model-preparation/llm-fine-tuning/)하여
    경쟁 우위를 확보합니다.
- **예측 가능한 성능과 제어**: LLM을 셀프 호스팅하면 시스템의 동작과 성능을
  완전히 제어할 수 있습니다. 애플리케이션의 성능과 가용성에 영향을 줄 수 있는
  외부 API의 요청 제한(rate limit)이나 갑작스러운 정책 변경에 휘둘리지 않습니다.

## 비교 요약 {#comparison-summary}

서버리스와 셀프 호스팅 LLM 추론 중 무엇을 선택할지는 사용 편의성, 데이터
프라이버시, 성능 최적화, 제어에 관한 구체적인 요구 사항에 따라 달라집니다.

| 항목                               | 서버리스 API                           | 셀프 호스팅 추론                               |
|------------------------------------|----------------------------------------|------------------------------------------------|
| **사용 편의성**                    | 높음(간단한 API 호출)                  | 낮음(LLM 배포 및 유지 관리 필요)               |
| **데이터 프라이버시 및 규정 준수** | 제한적                                 | 완전한 제어                                    |
| **커스터마이징**                   | 제한적                                 | 완전한 유연성                                  |
| **대규모 사용 시 비용**            | 높음(사용량 기반, 크게 늘어날 수 있음) | 잠재적으로 낮음(예측 가능하고 최적화된 인프라) |
| **하드웨어 관리**                  | 추상화됨                               | GPU 설정 및 유지 관리 필요                     |

## 비용을 어떻게 볼 것인가 {#how-to-think-about-costs}

서버리스 API에서는 토큰당 비용이 고정되어 있지만, 총지출은 사용량에 비례하여
선형으로 늘어납니다. 초기 프로토타이핑 단계에서는 괜찮지만, 프로덕션에서는 금방
비싸집니다.

셀프 호스팅은 초기 작업과 인프라 비용이 더 많이 듭니다. 하지만 규모가 커질수록
토큰당 비용이 크게 떨어지며,
[KV 캐시 오프로딩](/inference-optimization/kv-cache-offloading/) 같은 추론
최적화 기법을 사용하면 특히 그렇습니다.

AI 도입 단계에 따라 접근 방식을 재평가하고, 민첩성과 제어 사이의 트레이드오프를
따져 보는 것이 좋습니다.

또한 서버리스와 셀프 호스팅 모두 시간이 지나면서 저렴해지고 있다는 점도 주목할
만합니다. 그 이유는 다음과 같습니다.

- 경쟁 심화로 API 가격 인하가 계속되고 있습니다. 그림 1에서 보듯이, OpenAI 같은
  공급자가 시간이 지나면서 토큰 가격을 크게 낮춘 데서 이러한 추세가 뚜렷하게
  드러납니다.

- 다양한 최적화 기법 덕분에 더 적은 자원으로 더 좋은 성능을 내는 오픈소스 모델이
  나오고 있습니다.

## 언제 서버리스로 시작하고 언제 직접 제어할 것인가 {#when-to-start-serverless-and-when-to-take-control}

LLM을 막 시작하는 단계라면 서버리스 API는 빠르게 움직이기에 좋은 방법입니다.
서버리스 API는 프로토타이핑을 쉽게 하고, 진입 장벽을 낮추며, 인프라를 다루지
않고도 사용 사례를 검증할 수 있게 해 줍니다.

하지만 이러한 단순함에는 트레이드오프가 따릅니다. 서버리스 API를 쓰더라도 서빙에
관한 결정은 여전히 남습니다. 어떤 엔드포인트 유형을 쓸지, 서비스를 애플리케이션
및 데이터 시스템과 어떻게 연결할지, 프라이버시 경계를 어떻게 관리할지, 트래픽이
늘어날 때 지연 시간과 지출을 어떻게 판단할지 결정해야 합니다.

AI 사용 사례가 늘어나고 성능, 프라이버시, 차별화에 대한 요구도 커지면 서버리스의
한계를 무시하기 어려워집니다. 진지하게 AI 제품을 만드는 모든 회사에는 좋은 모델
이상의 것이 필요합니다. **추론 레이어야말로 모델에 생명을 불어넣는 요소입니다**.
서드파티 API에만 의존해도 앱을 출시할 수는 있겠지만, 장기적으로 필요한
제어권이나 경쟁 우위는 얻을 수 없습니다. 셀프 호스팅 추론과 비교하면, 서버리스
모델 API로는 성능 튜닝과 비용 최적화를 세밀하게 제어하기 어렵습니다. 다른 모든
사람과 똑같은 API를 호출할 뿐입니다. 그리고 이러한 커스터마이징의 부족은
오래가는 우위를 구축하는 능력을 크게 제약합니다.

1. **복합 AI 시스템**(compound AI system)은 최고의 팀들이 앞서 나가는
   비결입니다. 복합 AI 시스템은 여러 모델과 도구를 연결해 풍부하고 유연한
   워크플로를 만듭니다.
2. **맞춤형 추론 스택**을 사용하면 다양한 워크로드에서 정밀한 SLA와 비용 목표에
   맞춰 아키텍처를 설계할 수 있습니다.
3. **미세조정된 모델과 커스텀 모델**은 범용 API가 따라올 수 없는 도메인 특화
   정확도와 IP 보호를 제공합니다.

결국 **추론 품질이 곧 제품 품질입니다**. AI가 핵심 업무에 필수적이라면, 빠르고
안정적이며 안전하고 목표에 맞게 조정된 인프라가 필요합니다.

바로 그때가 API를 넘어 추론을 직접 소유해야 할 시점입니다.

## 셀프 호스팅을 선택하면 무엇을 해결해야 할까요? {#what-do-i-need-to-solve-if-i-choose-self-hosting}

셀프 호스팅을 하면
[LLM 추론 스택](/infrastructure-and-operations/what-is-llm-inference-infrastructure/)을
제어할 수 있지만, 그 운영 책임도 함께 집니다. GPU 서버 프로비저닝 외에도 다음
사항을 고려해야 합니다.

- **설정과 유지 관리를 위한 DevOps 시간**: 인프라 구축, 배포 관리, 시스템의
  원활한 운영 유지
- **모니터링 및 알림 시스템**: 성능을 추적하고, 장애를 감지하고, SLA를 유지하기
  위한 관측 가능성 구현(TTFT, TPS 같은 LLM 특화 지표 포함)
- **데이터 전송 및 스토리지 비용**: 대용량 모델 파일 처리와 클라우드 대역폭 또는
  디스크 I/O 비용 관리
- **잠재적 다운타임과 이중화 비용**: 고가용성 보장과 하드웨어 또는 서비스 중단에
  대비한 장애 조치(failover) 계획
- **느린 콜드 스타트**: GPU 인스턴스 부팅, LLM 컨테이너 풀(pull), 모델 가중치의
  메모리 적재가 여기에 포함됩니다. 실시간 워크로드나 트래픽이 급증하는
  워크로드에 대응해 빠르게 확장하려면 시작 시간 최적화가 매우 중요합니다.

그렇다고 모든 것을 처음부터 직접 구축해야 하는 것은 아닙니다. 추론 플랫폼을
사용하면 이러한 비용을 줄이고 운영 부담을 덜 수 있으며, 장기적으로 비용 효율을
높일 수도 있습니다.

<ContactCallout>

완전 관리형 추론 플랫폼에 배포하는 데 관심이 있다면, 저희는 확장 가능한 분산
아키텍처와 맞춤형 추론 최적화로 기업이 오픈 LLM과 커스텀 LLM을 호스팅할 수
있도록 돕고 있습니다.

## 자주 묻는 질문 {#faqs}

### 셀프 호스팅 AI란 무엇인가요? {#what-does-self-hosted-ai-mean}

셀프 호스팅 AI란 자체 인프라(예: 온프레미스 데이터 센터, 프라이빗 클라우드, 전용
GPU 서버)에서 AI 모델을 실행하고 관리하는 것을 말합니다.

셀프 호스팅을 하면 데이터 프라이버시, 성능 튜닝, 비용 최적화를 완전히 제어할 수
있습니다. 다음이 필요한 팀에 유용합니다.

- DeepSeek-R1 같은 오픈소스 모델 배포
- 특정 최적화 기법을 사용한 모델 커스터마이징
- 독점 데이터를 사용한 모델 미세조정
- 내부 규정 준수 또는 데이터 주권 요구 사항 충족

### 독점 모델이 오픈소스 모델보다 더 강력한가요? {#are-proprietary-models-more-powerful-than-open-source-models}

항상 그렇지는 않습니다. 목표에 따라 다릅니다.

독점 모델은 방대한 데이터셋으로 학습되고 고급 정렬(alignment) 기법으로
다듬어지기 때문에 범용 추론, 코딩, 대화 품질에서 앞서는 경우가 많습니다.
인프라를 관리하지 않고 높은 성능을 바로 쓰고 싶다면 훌륭한 선택입니다.

Llama, Qwen, DeepSeek 같은 오픈소스 모델은 훨씬 더 많은 제어권, 투명성, 유연성을
제공합니다. 오픈소스 모델은 미세조정할 수 있고, 어디에든 배포할 수 있으며, 지연
시간과 비용에 맞게 최적화할 수 있습니다. 오픈 모델과 독점 모델의 격차는 빠르게
좁혀졌으며, 특히 도메인 특화 워크로드에서 그렇습니다.

예를 들어 법률, 의료, 금융 분야에서 독점 데이터로 오픈소스 LLM을 미세조정하면,
