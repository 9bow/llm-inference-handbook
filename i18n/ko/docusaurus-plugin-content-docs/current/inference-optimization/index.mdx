# 추론 최적화

LLM을 실행하는 것은 출발점일 뿐입니다. LLM을 빠르고 효율적이며 확장 가능하게
만드는 데 필요한 것이 바로 추론 최적화입니다.

## 추론을 최적화해야 하는 이유 {#why-do-you-need-to-optimize-inference}

데모에서 잘 동작하던 구성도 실제 트래픽에서는 실패할 수 있습니다. 대기열이
생기면 지연 시간이 늘어나고, 처리량이 하드웨어 용량에 못 미치는 수준에서
정체되며, 비용이 예상보다 빠르게 증가할 수 있습니다. 프로덕션에서 최적화는
제품이 감당할 수 있는 비용으로 지연 시간과 처리량 목표를 달성하도록 도와줍니다.

최적화를 하면 트레이드오프도 더 잘 통제할 수 있습니다. 어떤 워크로드는 대화형
사용자를 위해 낮은 지연 시간이 필요합니다. 어떤 워크로드는 배치 작업을 위해 최대
처리량이 필요합니다. 긴 컨텍스트 애플리케이션에는 세심한 KV 캐시 관리가
필요합니다. 멀티 테넌트 시스템에는 한 워크로드가 다른 워크로드에 피해를 주지
않도록 막는 라우팅 및 스케줄링 정책이 필요합니다.

서버리스 엔드포인트(예: OpenAI API)를 사용한다면 이런 작업의 상당 부분이
추상화되어 있지만, 트레이드오프는 여전히 가격, 요청 제한(rate limit), 응답
시간에 영향을 줍니다. 오픈소스 모델이나 커스텀 모델을 셀프 호스팅한다면, 적절한
최적화 기법을 적용해야 기본 런타임이 주는 대로 받아들이지 않고 서빙 스택을 실제
워크로드에 맞출 수 있습니다.
